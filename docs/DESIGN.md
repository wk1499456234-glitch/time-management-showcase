# 設計書

## 1. 対象と画面構成

TimeWeaveの画面、データの流れ、保存と復旧の考え方を説明する。第1〜6節は現在の公開URL、第7節はサーバーに接続する環境の動作を扱う。モジュール名や保存・通信の実装は第8節の開発者向け補足にまとめる。機能の範囲は[要件定義書](REQUIREMENTS.md)、データの意味は[記録・集計定義書](RECORD-DEFINITION.md)に従う。

| ページ | 主な操作 | 直接開くリンク |
| --- | --- | --- |
| タイマー | 活動選択、計測、一時停止・再開・終了、原文入力、最近の成果 | `#/timer` |
| 記録 | 自分の終了済み活動の閲覧・原文編集、固定例への切り替え | `#/records`、固定例は`#/records/sample` |
| AI 振り返り | 固定例の週選択、時間分布、数量比較、保存済みAI本文・根拠 | `#/review` |
| 設定 | 表示言語、保存先の説明、JSONバックアップ・読み込み、AIの範囲 | `#/settings` |

ナビゲーションは広い画面では上部、狭い画面では下部に置く。各画面をリンクから直接開き、再読み込みやブラウザーの戻る・進むを使える。以前のタイマー・記録・バックアップへのリンクも引き続き利用できる。バックアップへのリンクでは設定内の該当箇所を開き、キーボードで操作できる位置へ移る。存在しないページ名を指定した場合はタイマーを開く。

## 2. 二つのデータの流れ

- **自分の試用記録**：タイマーや入力欄で行った操作を確認し、時間を計算してブラウザーへ保存する。保存できたかどうかを画面に返す。
- **架空の学習サンプル**：用意された原文・成果・AI説明を読み、選んだ週の統計と比較を表示する。

二つのデータを自動で混ぜたり、試用記録をAIへ送ったりすることはない。グラフと比較は記録の数値から作り、AIの説明は保存済みの文章を読む。

## 3. ブラウザー保存と失敗時の回復

試用記録はブラウザーに保存する。タイマーで入力中の文章は同じタブに一時保存し、ページを切り替えても計測状態や入力内容を保つ。ただし、入力途中の文章を閉じたタブや別の端末へ引き継げるとは限らない。既存の保存形式を引き継いでおり、画面の更新だけで以前の記録を消すことはない。

複数のタブから同時に保存する場合は、処理の順序をそろえ、ほかのタブで記録が変わっていないか確認する。変更や削除を検出したら上書きせずに知らせる。利用者は必要な内容を書き出して保全したうえで、保存済みのデータを読み直す。

保存できた場合、画面にだけ内容が残っている場合、変更がなかった場合を区別する。書き込みを拒否された操作はエラーとして伝え、画面に内容が見えるだけで保存成功とは表示しない。

保存に失敗した場合は変更内容を保持し、同じ内容で保存をやり直せるようにする。再試行のたびに成果や読み込んだ記録を追加することはない。未保存の変更に別の変更を重ねず、入力欄は成功を確認してから空にする。編集や読み込みに失敗した場合も、その内容を残して再試行できるようにする。

同時保存を安全に制御できない環境や、読み込んだデータが壊れている場合は警告する。画面を閉じると未保存の内容を失う可能性があるため、再試行またはJSONでの書き出しを案内する。

JSONの読み込みでは、ファイルの内容と件数を確認してから実行する。すでに同じ内容で保存されている記録は重複して追加しない。同じ記録なのに内容が異なる場合や、活動の時間が矛盾する場合、進行中の活動が複数になる場合などは読み込みを拒否する。書き出しには原文・日時・一時停止・進行中の保存状態を含み、固定例やAI結果は含めない。

## 4. 固定例との分離と通信

固定例は配信ファイルに含まれる読み取り専用データ。訪問者データはブラウザーの別領域に保存する。試用入力が固定例の解析や振り返りへ流れ込む経路はなく、固定例を訪問者本人の分析として使わない。

現在の公開URLにはログインや新たなAI生成の機能はなく、入力を記録用サーバーやAIへ送る処理もない。ブラウザー保存は厳密なアカウント別管理ではないため、同じサイト上の別アプリから完全に独立した保存場所だとはみなさない。詳しい通信・保存範囲は第8節に記載する。

## 5. 表示、動き、アクセシビリティ

冷たい白の背景に、黒に近い本文と読みやすい灰色の補足を組み合わせ、タイマーと入力を中心に配置する。編み目の図形は独立した画像素材で、ボタンや文字は操作・表示できる画面の部品として作る。

ページ切り替えとスクロールによる段階的表示は別に扱う。タイマー、入力、主な操作、保存・エラー表示はすぐ利用できる。後続の内容はまとまりごとに表示し、一度読んだ内容を戻るたびに隠さない。端末の「動きを減らす」設定に従い、表示効果の開始に失敗しても本文を読めるようにする。

キーボードで本文へ移動するリンクや、ページ移動後の操作位置を設ける。詳細は開閉でき、狭い画面の比較は週ごとにまとめる。スマートフォンの画面上のキーボードや画面端の操作領域に配慮した処理はあるが、すべての実機で動作を確認したわけではない。

## 6. プログラムとAIの役割

時間、数量、単位別の合計や比較はプログラムが計算し、成果の整理状況も表示する。AIの役割は原文から成果を整理し、統計に基づく説明と提案を行うことである。AIに集計値を決めさせたり、利用者の目標を勝手に設定させたりしない。

固定例の表示は、保存済み結果の閲覧を担当する。原文、AIの解析、人の確認、数量比較、保存されたAI本文を別々に参照できる。簡潔な比較表示のために保存済みAI本文を文字列置換で書き換えない。

## 7. サーバーに接続してAIを利用する場合

別の実行環境では、記録の保存とAI処理を行うサーバーを使う。アクセスコードでログインし、アカウントごとに記録を分けて保存する。この公開リポジトリにはサーバー自体は含まれない。

原文を保存してからAIで整理し、結果が遅れて届いても、更新した原文や人の修正を上書きしない。振り返りの作成・更新は利用者が操作したときだけ行う。AIへの接続に必要な認証情報はサーバーで管理し、利用の許可、設定と費用上限を確認する。複数の処理が重なっても上限を越えないよう、処理前に必要な費用枠を確保する。再試行や結果が分からない処理も管理対象に含め、結果を読むだけでは新たなAIの生成料金は発生しない。

サーバーから書き出すJSONは元の記録を保存する。整理した成果や振り返りを含めて復旧するには、データベース全体のバックアップを使う。ブラウザーのJSON書き出しを、サーバー全体のバックアップの代わりにはできない。

## 8. 開発者向け補足

### モジュールと処理経路

```text
利用者の操作
  App / Outputs / LocalDataPanel
    → browserEngine → useSessionEngine
      → LocalSessionStore（ロック・競合・保存結果）
        → sessionData（入力検証・状態遷移・時間計算）
        → localStorage（試用記録）

固定例 ai-demo.json
  → DemoPages（原文・整理成果・確認内容）
  → ReviewPage / comparisonData / ReviewComparison
    → 選択週の統計・比較・保存済みAI説明
```

表示言語は`i18n`、動きは`motion`と`scrollReveal`が担当する。ルート解析は[共通実装](../src/ui/routes.ts)を画面とテストで使用する。URLの`#`以降を使うことで、GitHub Pagesのサブパスでも直接アクセス・再読み込み・戻る・進むを扱う。旧`#timer`、`#records`、`#backup`を維持し、`#/settings/backup`では唯一のバックアップ領域を展開してフォーカスする。

### 保存・通信・表示の制御

- 試用記録は`localStorage`、タイマー入力中の草稿は`sessionStorage`に保存する。保存キーと形式バージョンは従来どおり。
- 同一オリジン（通信方式・ホスト名・ポートの組み合わせ）のWeb Locksで保存を直列化し、操作前に保存値を照合する。メモリーに保持した操作の識別情報を使って再試行時の重複を防ぐ。
- JSON読み込みでは同一識別子・同一内容を重複として扱い、識別子が一致して内容が異なる場合は拒否する。図形は独立したSVG、操作部はコンポーネントとして実装する。
- 保存結果は`saved`（ブラウザーへの保存成功）、`memory-only`（メモリーのみ）、`unchanged`（変更なし）を区別し、画面は保存成功だけを成功として扱う。
- 公開用ビルドのCSP（ブラウザーの通信制限）は`connect-src 'none'`。API通信を禁止し、アプリのリソースは相対パスで取得する。ブラウザー保存の境界はオリジンであり、同じオリジン内の保存キーを分けるだけでは、別アプリからの厳密な隔離にならない。
- 動きを減らす設定は`prefers-reduced-motion`で判断する。ソフトキーボードへの対応は`visualViewport`、画面端の安全領域への配慮はCSSで実装する。実機で確認した範囲は[検証記録](VALIDATION.md)に従う。

### サーバー側の構造

実装済みの別環境は、Reactの画面と同一オリジンのFastAPI、SQLiteによる保存で構成する。ログイン状態はサーバー側セッションで管理する。AI結果には入力データの版と言語を関連付け、古い結果による上書きを防ぐ。アカウント単位の権限・設定・利用上限と、サービス全体の費用の事前確保を確認する。SQLite完全バックアップは、整理成果と振り返りも含む運用上の復旧用である。
