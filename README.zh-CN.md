# 时间管理 — 一起记录时间与成果

[在线体验](https://wk1499456234-glitch.github.io/time-management-showcase/) · [GitHub 仓库](https://github.com/wk1499456234-glitch/time-management-showcase) · [日本語](README.md)

## 为什么做

回顾工作或学习时，只知道“花了多少分钟”，还不能说明事情推进了多少。因此，这个工具把活动时间和“做成了什么”放在一起记录。例如，学习后写下“确认了类型差异，完成了一个示例”，就能把时间与成果联系起来。这段成果文字在软件里叫作 Output。

作者希望它只记录主动开始的活动，操作简单，界面安静、清楚。不监控全天生活，也不为所有活动打一个统一的“效率分数”。

作者负责用途、需求、范围、界面要求和试用反馈，并决定怎样检查才算符合使用要求。AI 协助代码实现、问题调查、测试和文档整理。这不意味着作者手写了全部代码，也不意味着所有自动测试都由作者亲手操作。

## 做了哪些功能

当前是可以体验以下功能的公开展示版：

- 4 种固定活动的开始、暂停、恢复和结束；同一时间只计时一个活动。
- 运行时添加、编辑 Output；结束后也可从今日记录编辑文字。
- 结束时显示总经过时间、暂停时间、实际活动时间与 Output 汇总。
- 今日记录，以及以 8 小时为基准的利用率和剩余时间。
- 保存到浏览器、刷新后恢复、导出和导入 JSON 格式的备份文件。
- 日文、中文界面切换；不翻译用户输入和导入记录。

## 遇到哪些问题，怎样解决和检查

开发先从“开始活动、写下成果”的画面做起，再完善时间计算和保存方式。以下包括已有记录支持的问题，以及为防止出错而专门检查的场景。

### 刷新页面后，记录消失

学习过程中刷新页面，之前花的时间和写下的 Output 应该还在。但早期原型只把记录放在打开的页面中，刷新后这些内容就会丢失。

处理方法是每次操作后，把当前活动和完成记录保存到浏览器。验证时分别在运行中、暂停中刷新，确认活动状态和 Output 能恢复。公开页面也实际操作了开始、保存和刷新恢复。

### 暂停休息时，时间会不会继续增加

工作中途休息，如果暂停的时间也算作活动时间，就无法准确回顾投入。因此，“暂停期间不增加有效时间”被列为检查要求。

软件从开始到结束的总时间中扣除暂停时间。验证时暂停并等待，确认有效时间不增加；刷新后仍保持暂停，恢复后才继续计时。这是已检查的行为，不表示曾经实际发生过把休息时间错误累加的故障。

### 两个页面同时打开并编辑

在同一个浏览器打开两个页面时，其中一个页面可能已保存新内容，另一个还停留在旧内容。如果旧页面直接保存，就可能盖掉新记录。

因此，保存操作会依次进行；发现另一个页面先改了内容，就停止覆盖并显示提醒。此时应先导出当前页面的备份，再读取最新数据。保存逻辑的自动测试和使用真实浏览器保存功能的试验，检查了旧内容不能破坏新记录。尚未进行把两个产品页面并排、同时手动编辑的验收。

### 同一个备份重复导入

恢复备份后，可能会再次选中同一个文件。如果每次导入都增加一份相同活动，记录就不可信了。此外，来源版本有一项修复：备份中项目的排列顺序不同，曾被误判为记录内容不同。

现在会检查记录的身份以及文字、时间等内容，完全相同的记录直接跳过。如果同一条记录内容不同，或活动时间重叠，就中止整次导入，保留原记录。验证时实际导出文件并再次导入，确认没有增加重复记录；项目顺序不同、文件内容异常等情况也有自动测试覆盖。

这些验证由 AI 协助执行，并非把每个例子都描述成作者亲历的失误。具体方法和未验证范围见[验证记录](docs/VALIDATION.md)，代码来源见[来源说明](PROVENANCE.md)。

## 从 AI 辅助开发中学到了什么

比起只说“做一个时间管理软件”，说明“休息时不要累计时间”“刷新后要保留文字”等使用场景和预期结果，更容易明确应该检查什么。

AI 回答“完成了”并不足以证明可用，还要看实际操作和测试结果。把作者决定的用途、范围，与 AI 协助的实现、调查区分开，也更容易解释每个功能为什么这样做。明确告诉读者哪些功能还没完成，同样是开发说明的一部分。

## 完整体验步骤

1. 点击“TypeScript学习”的“开始”，等几秒。
2. 在 Output 输入“确认了类型差异”，点击“追加”；可用“修改”编辑文字。
3. 点击“暂停”并等待，确认时间不增加，再刷新页面。
4. 点击“恢复”，等一会后“结束”，查看汇总和今日记录。
5. 展开今日记录的 Output，编辑文字，再刷新确认保存。
6. 展开“本地数据与备份”，点击“导出 JSON 备份”，把文件另存到安全位置。
7. 用“导入 JSON”选择同一个文件，确认合并，检查记录没有重复增加。

运行时关闭页面仍会累计时间；中断请暂停，完成请结束。汇总向下取整到分钟，因此短时间试用可能显示 0 分钟。

## 数据保存与真实限制

记录仅保存在**每位访客当前使用的浏览器内**，没有服务器保存，也没有跨设备同步。记录不会发送给作者或其他访客。**清除网站数据会丢失记录。** 结束隐私浏览、更换浏览器、设备或网站地址，也可能导致记录丢失或不可见。请定期导出 JSON 备份。备份包含输入的文字，不要提交到公开仓库。

浏览器容量不足或无法使用保存功能时会显示警告。如果有尚未保存的记录，请在关闭或刷新页面前导出备份。

活动固定为 4 种，每日基准固定为 8 小时。历史、分析、设置页面仍在开发中。旧日期记录保留在备份中，但没有按日期查看的页面。手动修改时间、账号、AI 分析均未实现。计时依赖设备时钟。尚未在真实 iPhone/Safari 上验收。

后续考虑历史浏览、活动和基准时间设置、服务器保存以及访客数据隔离等，均不是当前已经可用的功能。

## 本地运行与构建

准备 Node.js 22 以上及 npm，在本目录执行：

```sh
npm ci
npm run dev -- --host 127.0.0.1
```

`npm ci` 按锁文件安装依赖；`dev` 启动开发服务器，打开终端显示的网址即可。

```sh
npm run typecheck
npm test
npm run build
npm run check:public
npm run preview -- --host 127.0.0.1 --port 5196 --strictPort
```

依次用于类型检查、计时/保存回归测试、生成 `dist/`、检查公开文件和构建内容、预览生产构建。不要直接双击 HTML，应通过 HTTP 服务器访问。开发和预览端口不同，浏览器记录也相互独立。
