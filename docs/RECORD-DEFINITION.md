# 記録・集計定義書

TimeWeaveに記録する文章、整理された成果、時間と数量の意味を説明する。第1〜6節は現在の公開URLで保存・閲覧できる内容、第7節はサーバーに接続してAIを利用する環境を扱う。保存データの項目名や形式は、第8節の開発者向け補足にまとめる。

## 1. 活動、計測、原文

活動は「AI開発」「TypeScript学習」「TOEIC」「運動」の固定候補から選ぶ。一回の計測（セッション）は一つの活動に属する。開始、終了、一時停止区間を持ち、進行中の計測は同時に一つまで。

一回の計測には複数の成果原文を保存できる。原文は、利用者が入力した文章そのもの。計画、未完了の内容、数量のない理解や感想も含めて保持する。原文中の数量をそのまま完成量とみなさない。

原文の前後の空白と改行はそのまま保存するが、空白だけの入力は保存しない。文章を編集しても同じ記録として扱い、記録した時刻を変えない。現在の公開URLでは、訪問者の文章をAIで整理しないため、その文章に成果の数量・分類・確認状態は付かない。

## 2. 固定例の整理成果

固定例は閲覧用に用意したサンプルで、訪問者の試用記録や読み込み用のバックアップとは別のデータである。一つの原文から、複数の成果に整理される場合がある。

| 表示する内容 | 意味 |
| --- | --- |
| 原文 | 入力した文章そのもの。成果の表示名やAIの説明と分けて残す |
| 整理された成果 | 内容・数量・単位・分類と、原文のどこを根拠としたかを示す引用 |
| AIによる元の整理結果 | 実際にAIで整理した記録に保存している結果。人が確認した後の成果と区別する |
| 人が確認した内容 | 分類など、どの内容を人が確認したかの説明 |
| 成果の由来 | 比較の背景として用意したものか、AIで整理した後に人が確認したものかの区別 |

分類は同じ種類の成果をまとめるために使う。内容は単独で読める成果名、引用根拠は原文内の該当箇所であり、同じ役割ではない。あらかじめ用意した背景成果をAI出力として表示しない。由来と五週の構成は[出典・来歴](../PROVENANCE.md)に記載する。

数量を付けていない成果は、ゼロという意味ではない。数量が0の記録は、ゼロという数値が明示された場合に限る。AIでまだ整理していない記録や、記録そのものがない状態を、成果ゼロとして補わない。復習した語数から習得語数、解いた問数から正解数は算出しない。

## 3. 数量の集計

固定例では、同じ分類かつ同じ単位の成果をまとめて比較する。現在は保存された分類名と単位名が完全に一致するものを対象とし、意味が似た名前の自動統合や単位換算は行わない。語・問・ページを足し合わせず、数量のない成果は文章として残す。

固定例の週集計は、元の記録と一致することを確認して保存している。画面の比較値と七日間のグラフは、これらの記録からプログラムが作る。グラフの形や値を参考画像から転記しない。

## 4. 有効時間と日付

有効時間は、開始から終了までの経過時間から一時停止の合計を引く。進行中は現在時刻まで、停止中は未終了の停止区間も差し引く。ミリ秒を保持し、時計の表示は秒未満を切り捨てた`H:MM:SS`。表示が0秒でも、保存値が厳密に0とは限らない。

日付、成果の時刻、「今日」の範囲はすべて日本時間にそろえる。端末のタイムゾーン（時刻を表示する地域）を変えても日別の合計は変わらない。例えば東京11月19日00:30に、11月18日18:00〜18:30の活動を「今日」に加算しない。

日をまたぐ計測は、各日の00:00以上・翌日00:00未満に重なる部分から、その日の一時停止を差し引く。「記録」の日付未選択時は開始日で活動をまとめる。日付を選ぶと、その日に重なる活動を表示する。日別合計はその日の有効時間、活動行の時間はその活動全体であり、両者の意味は異なる。

固定例の七日間グラフは、その週の各記録と一時停止から日別に計算する。棒のラベルは分単位で切り捨て、展開すると秒表示を確認できる。記録のない日は「記録なし」であり、実際に活動しなかったことの証明ではない。

## 5. 週と比較

週の範囲は東京時間の月曜00:00以上、次の月曜00:00未満。現在の公開URLでの週選択は固定例の五週に限られ、訪問者の試用記録をここへ混ぜない。

「前週」は選択週の直前の一週。「前4週平均」は直前の連続する四週を対象とし、次の条件で計算する。

- 時間平均は四週すべてのデータがあるときだけ合計を4で割る。三週だけの平均を四週平均と呼ばない。
- 数量平均は四週とも原文があり、整理が完了し、未解析・処理中・失敗・未確認がなく、同じ分類と単位の数量が四週すべてにあるときだけ計算する。
- ある週に該当する分類・単位がない場合は、勝手にゼロを補わず比較不足として扱う。
- 整数は小数点以下を付けずに表示する。端数のある数量は小数として表示し、元の保存値を変更しない。表示精度は第8節に記載する。

解析状況は原文の整理状況と未確認の成果を区別する。原文件数と未確認成果件数は同じ単位とは限らず、一つの原文から複数の成果が生じる。解析していないこと、記録が存在しないこと、解析済みで完成成果がないことは別の状態である。

## 6. AI説明と保存結果

固定例のAI振り返りには、対象週について保存した日本語の説明・発見・最大2件の提案・判断上の制約が含まれる。重要な発見にはその週または比較週の根拠がある。説明文は集計値を置き換えず、簡潔な数量差はプログラムで別に表示する。

自分の試用記録を変更しても、固定例の分析は更新されず、更新が必要な状態にもならない。両者は別のデータである。言語を変えてもAI本文を翻訳・再生成しない。

## 7. サーバーに接続してAIを利用する場合

AI処理を行うサーバーに接続した環境では、原文、AIで整理した成果、人による修正と分類の確認をサーバーに保存する。AIへ処理を依頼するのは原文を保存した後である。どの時点の原文を使ったかを管理し、結果が遅れて届いても、新しい原文や人の修正を上書きしない。AIの処理に失敗しても原文と時間の記録を保ち、新しい分類を本人の確認なしに確定しない。

時間は一時停止を除いた実際の時間帯、成果は原文を記録した時刻に基づいて、どの週に入るかを決める。分類が未確認の成果は正式な数量合計に入れない。途中の週には集計した時点を示し、終了した過去四週全体との比較と、同じ曜日・時刻までの比較を区別する。比較できる過去の記録、予算、目標などの不足を明示し、短い期間から効率や長期傾向を断定しない。

振り返りには、作成に使った時点の記録、言語、AIの種類、作成時刻を関連付けて保存する。対象の原文・整理成果・比較する過去の記録が変わると、更新が必要であることを示す。生成中にデータが変わった結果も最新として扱わない。更新に失敗しても前の結果は読める。閲覧や再読み込みだけで作り直すことはない。この仕組みはサーバー上の記録が対象で、公開URLの固定例を書き換えるものではない。

## 8. 開発者向け補足

### ブラウザー保存の項目と形式

実装の参照先は[型定義](../src/types/index.ts)と[保存形式・計算](../src/state/sessionData.ts)。次のバージョンは製品のリリース番号ではなく、ブラウザー保存データの形式を示す。

| 対象 | 主なフィールド | 意味 |
| --- | --- | --- |
| 保存全体 | `format`, `version`, `revision`, `sessions`, `current` | 保存形式の識別子は `time-management-local`、データ形式のバージョンは `1`。終了済みの計測を配列で保持し、進行中の計測は1件、存在しない場合は `null` とする。 |
| 共通の計測情報 | `id`, `activityId`, `startAt`, `pauseIntervals`, `outputs` | 識別子、活動、開始時刻、一時停止、原文の配列 |
| 進行中 | `lastAt`, `status` | 最終操作時刻と`running`／`paused` |
| 終了済み | `endAt`, `elapsedMs`, `pauseMs`, `activeMs` | 終了時刻と、経過時間・一時停止時間・有効時間（ミリ秒） |
| 一時停止 | `start`, `end` | 区間の開始と終了。現在停止中の終了は`null` |
| 成果原文 | `id`, `text`, `createdAt` | 原文の識別子、文字列、記録時刻。編集しても識別子と記録時刻を保持 |

時刻はUnix時刻のミリ秒で保存する。ブラウザー保存の原文には、整理成果の数量・分類・確認状態のフィールドはない。保存全体の`revision`は他のタブとの変更の競合を検出するための値であり、AI解析が参照する原文の版番号ではない。

### 固定例の項目と集計の実装

[ai-demo.json](../src/data/ai-demo.json)は読み取り専用の別形式で、旧JSONバックアップとして取り込むものではない。

| フィールド | 意味 |
| --- | --- |
| `raw` | 元の文章 |
| `items` | 確認後の成果。`content`は内容、`quantity`は数量または`null`、`unit`は単位、`type`は分類、`source_quote`は引用根拠 |
| `aiItems` | 実際のAIによる元の解析がある記録にだけ保存された内容 |
| `confirmation` | 人が確認した内容の説明 |
| `source` | 背景として用意した成果と、AIで整理した後に人が確認した成果の区別 |

`quantity: null`は数量なし、`quantity: 0`は数値のゼロ。比較は`type`と`unit`の完全一致を使う。週集計と元記録の一致は[回帰テスト](../tests/demo.test.ts)で再計算して確認する。[比較処理](../src/ui/comparisonData.ts)の数値表示は、小数部を最大12桁まで扱い、整数の不要な`.0`を省く。

日時と日次境界は`Asia/Tokyo`、時計の表示は秒未満を切り捨てた`H:MM:SS`。サーバー上の振り返りは入力データの版、言語、モデル、生成時刻を持ち、更新が必要かどうかの判定に使う。これはブラウザー保存の`revision`とは別の管理である。
