# 設計書

## 1. 対象と画面構成

TimeWeaveの画面、データの流れ、保存と復旧の設計を説明する。第1〜6節は現在の公開URLを構成する実装、第7節はバックエンド接続環境の構造を扱う。現在の範囲は[要件定義書](REQUIREMENTS.md)、データの意味は[記録・集計定義書](RECORD-DEFINITION.md)に従う。

| ページ | 主な操作と責務 | ルート |
| --- | --- | --- |
| タイマー | 活動選択、計測、一時停止・再開・終了、原文入力、最近の成果 | `#/timer` |
| 記録 | 自分の終了済み活動の閲覧・原文編集、固定例への切り替え | `#/records`、固定例は`#/records/sample` |
| AI 振り返り | 固定例の週選択、時間分布、数量比較、保存済みAI本文・根拠 | `#/review` |
| 設定 | 表示言語、保存先の説明、JSONバックアップ・読み込み、AIの範囲 | `#/settings` |

ナビゲーションは広い画面では上部、狭い画面では下部に置く。ルート解析は[共通実装](../src/ui/routes.ts)を画面とテストで使用する。ハッシュを使うため、Pagesのサブパスでも直通・再読み込み・戻る・進むを扱える。旧`#timer`、`#records`、`#backup`を維持し、`#/settings/backup`も唯一のバックアップ領域を展開してフォーカスする。未知のルートはタイマーへ戻す。

## 2. モジュールとデータの流れ

```text
利用者の操作
  App / Outputs / LocalDataPanel
    → browserEngine → useSessionEngine
      → LocalSessionStore（ロック・競合・保存結果）
        → sessionData（入力検証・状態遷移・時間計算）
        → localStorage（試用記録）

固定例 ai-demo.json
  → DemoPages（原文・整理成果・確認内容）
  → ReviewPage / comparisonData / ReviewComparison
    → 選択週の統計・比較・保存済みAI説明
```

二つの経路の間に自動取り込み・解析はない。`i18n`が表示言語を、`motion`と`scrollReveal`が動きを担当する。グラフと比較はデータから描画し、AI説明は保存済み文章を読む。

## 3. ブラウザー保存と失敗時の回復

試用記録は`localStorage`、タイマー入力中の草稿は`sessionStorage`に保存する。保存キーとデータ形式のバージョンは従来のブラウザー保存と共通である。画面切り替えでは計測状態と草稿を失わない。草稿は同じタブの一時保存であり、閉じたタブや別端末への引き継ぎを保証しない。

保存は同一オリジンのWeb Locksで直列化し、読み込んだ保存値を操作直前に比較する。他タブの変更・削除を検出した場合は勝手に上書きしない。利用者は必要な内容を書き出したうえで、明示的に保存済みデータを再読み込みする。

保存結果は永続保存成功（`saved`）、メモリーだけの保持（`memory-only`）、変更なし（`unchanged`）を区別する。拒否された操作はエラーとして扱う。上位の画面は永続保存成功だけを成功と判定する。

書き込み失敗時は、適用済みの変更と同じ操作の識別情報をメモリーに保持する。再試行はその保存をやり直し、成果追加や読み込みを再実行して二重に増やさない。未保存中に別の変更を重ねない。新規入力は成功確認後にだけ消し、原文編集は失敗時に閉じず、読み込み候補も成功前に捨てない。

ロックを使用できない環境や読み込み時点で壊れた保存データがある場合は、無理に永続保存を続けず警告する。画面を閉じるとメモリー上の未保存分を失う可能性があるため、再試行またはJSON書き出しを案内する。

JSON読み込みは形式検証と件数のプレビューを経て実行する。同一識別子・同一内容は重複させず、識別子の衝突、活動の時間的矛盾、複数の進行中活動などを拒否する。書き出しには原文・日時・一時停止・進行中の保存状態を含み、固定例やAI結果は含めない。

## 4. 固定例との分離と通信

固定例は配信ファイルに含まれる読み取り専用データ。訪問者データはブラウザーの別領域に保存する。試用入力が固定例の解析や振り返りへ流れ込む経路はなく、固定例を訪問者本人の分析として使わない。

公開ビルドにはバックエンド、ログイン、AI呼び出しを含めない。CSPは`connect-src 'none'`でAPI通信を禁止し、アプリのリソースは相対パスで取得する。ブラウザー保存の境界はオリジンであり、同一オリジン上の別アプリからの厳密な隔離を名前空間だけで保証するものではない。

## 5. 表示、動き、アクセシビリティ

冷白の背景、近黒の本文、冷灰の補足情報を使い、タイマーと入力を中心に配置する。編み目の図形は独立したSVGで、ボタンや文字は実際のコンポーネントとして実装する。

ページ切り替えとスクロールによる段階的表示は別に扱う。計時、入力、主操作、保存・エラー表示はすぐ利用できる。後続の内容をまとまりごとに表示し、一度読んだ内容を戻るたびに隠さない。`prefers-reduced-motion`を尊重し、動きの初期化が失敗しても本文は見える。

キーボード用の本文への移動リンク、ページ移動時のフォーカス、開閉できる詳細、スマートフォンで週ごとにまとめる比較表示を備える。ソフトキーボードを考慮する`visualViewport`処理と安全領域のCSSはあるが、すべての実機での動作を検証済みとはしない。

## 6. プログラムとAIの役割

プログラムが時間、数量、単位別合計、比較、解析状況を計算・表示する。AIは原文から成果を整理し、統計をもとに説明と提案を行う。計算の権威や利用者の目標設定をAIに委ねない。

固定例の表示は、保存済み結果の閲覧を担当する。原文、AIの解析、人の確認、数量比較、保存されたAI本文を別々に参照できる。簡潔な比較表示のために保存済みAI本文を文字列置換で書き換えない。

## 7. バックエンド接続環境の構造

実装済みのバックエンド接続環境は、Reactの画面と同一オリジンのFastAPIバックエンド、SQLite永続保存からなる。アクセスコードによるログインとサーバー側セッションでアカウントのデータを分離する。これは本リポジトリから起動できるサーバー機能ではない。

原文保存後の解析タスクは版を確認し、人が修正した内容を遅い結果で上書きしない。振り返り生成は利用者の操作で始め、保存結果・入力版・言語を管理する。サーバーだけがモデルの資格情報を持ち、アカウントの権限・設定・利用上限とサービス全体の費用予約を確認する。再試行、並行処理、結果不明の予約も費用管理の対象とする。読み込みは有料生成を起動しない。

サーバーのJSON書き出しは元の記録を扱う。SQLite完全バックアップは整理成果や振り返りも含む、運用上の復旧用である。ブラウザーのJSON書き出しは完全なサーバーバックアップの代わりにはならない。
