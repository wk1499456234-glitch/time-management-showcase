# 記録・集計定義書

TimeWeaveの原文、整理成果、時間と数量の意味を定義する。ブラウザー保存の実装と固定例を基準とし、バックエンド接続環境の版管理・解析・振り返り保存は第7節にまとめる。

## 1. 活動、計測、原文

活動は「AI開発」「TypeScript学習」「TOEIC」「運動」の固定候補から選ぶ。一回の計測（セッション）は一つの活動に属する。開始、終了、一時停止区間を持ち、進行中の計測は同時に一つまで。

一回の計測には複数の成果原文を保存できる。原文は、利用者が入力した文章そのもの。計画、未完了の内容、数量のない理解や感想も含めて保持する。原文中の数量をそのまま完成量とみなさない。

ブラウザーに保存するデータは、[型定義](../src/types/index.ts)と[保存形式・計算](../src/state/sessionData.ts)に従う。次の表にあるバージョンは、製品のリリース番号ではなく、ブラウザー保存データの形式を示す。

| 対象 | 主なフィールド | 意味 |
| --- | --- | --- |
| 保存全体 | `format`, `version`, `revision`, `sessions`, `current` | 保存形式の識別子は `time-management-local`、データ形式のバージョンは `1`。終了済みの計測を配列で保持し、進行中の計測は1件、存在しない場合は `null` とする。 |
| 共通の計測情報 | `id`, `activityId`, `startAt`, `pauseIntervals`, `outputs` | 識別子、活動、開始時刻、一時停止、原文の配列 |
| 進行中 | `lastAt`, `status` | 最終操作時刻と`running`／`paused` |
| 終了済み | `endAt`, `elapsedMs`, `pauseMs`, `activeMs` | 終了時刻と、経過時間・一時停止時間・有効時間（ミリ秒） |
| 一時停止 | `start`, `end` | 区間の開始と終了。現在停止中の終了は`null` |
| 成果原文 | `id`, `text`, `createdAt` | 原文の識別子、文字列、記録時刻。編集しても識別子と記録時刻を保持 |

時刻はUnix時刻のミリ秒。原文の前後の空白・改行を保存し、空白だけの入力は拒否する。ブラウザーに保存する原文には、整理成果の数量・分類・確認状態のフィールドはない。保存全体の`revision`は競合を検出するための値であり、AI解析が参照する原文の版番号ではない。

## 2. 固定例の整理成果

[固定例](../src/data/ai-demo.json)は訪問者の保存形式とは別の読み取り専用データで、旧JSONバックアップとして読み込むものではない。一つの`raw`から複数の整理成果が生じる場合がある。

| フィールド | 意味 |
| --- | --- |
| `raw` | 元の文章。成果の表示名やAI説明と分けて保持する |
| `items` | 確認後の成果。`content`は内容、`quantity`は数量または`null`、`unit`は単位、`type`は分類、`source_quote`は引用根拠 |
| `aiItems` | 実モデルによる元の解析がある記録だけに保存された解析内容。確認後の分類と区別する |
| `confirmation` | 人が何を確認したかを示す説明 |
| `source` | 背景として作成した成果と、実AI解析後に人が確認した成果の区別 |

分類は同じ種類の成果をまとめるために使う。内容は単独で読める成果名、引用根拠は原文内の該当箇所であり、同じ役割ではない。あらかじめ用意した背景成果をAI出力として表示しない。由来と五週の構成は[出典・来歴](../PROVENANCE.md)に記載する。

`quantity: null`は数量を付けない文章の成果で、ゼロではない。数量`0`は明示されたゼロという数値である。未解析や欠落を`0`に変換しない。復習した語数から習得語数、解いた問数から正解数は算出しない。

## 3. 数量の集計

固定例の比較は`type`と`unit`の組が一致する成果ごとに行う。現在は文字列の完全一致が基準で、同義語の自動統合や単位換算は行わない。語・問・ページを足し合わせず、数量のない成果は文章として残す。

固定例の週集計は確認済みデータとして保存され、[回帰テスト](../tests/demo.test.ts)で元の記録との一致を再計算して確認する。画面の比較値と七日間のグラフは、このデータからプログラムが組み立てる。グラフの形や値を参考画像から転記しない。

## 4. 有効時間と日付

有効時間は、開始から終了までの経過時間から一時停止の合計を引く。進行中は現在時刻まで、停止中は未終了の停止区間も差し引く。ミリ秒を保持し、時計の表示は秒未満を切り捨てた`H:MM:SS`。表示が0秒でも、保存値が厳密に0とは限らない。

日付、成果の時刻、今日の境界はすべて`Asia/Tokyo`。端末のタイムゾーンを変えても同じ日次集計になる。例えば東京11月19日00:30に、11月18日18:00〜18:30の活動を「今日」に加算しない。

日をまたぐ計測は、各日の00:00以上・翌日00:00未満に重なる部分から、その日の一時停止を差し引く。「記録」の日付未選択時は開始日で活動をまとめる。日付を選ぶと、その日に重なる活動を表示する。日別合計はその日の有効時間、活動行の時間はその活動全体であり、両者の意味は異なる。

固定例の七日間グラフは、その週の各記録と一時停止から日別に計算する。棒のラベルは分単位で切り捨て、展開すると秒表示を確認できる。記録のない日は「記録なし」であり、実際に活動しなかったことの証明ではない。

## 5. 週と比較

週の範囲は東京時間の月曜00:00以上、次の月曜00:00未満。現在の公開URLでの週選択は固定例の五週に限られ、訪問者の試用記録をここへ混ぜない。

「前週」は選択週の直前の一週。「前4週平均」は直前の連続する四週を対象とする。[比較処理](../src/ui/comparisonData.ts)は次の条件を使う。

- 時間平均は四週すべてのデータがあるときだけ合計を4で割る。三週だけの平均を四週平均と呼ばない。
- 数量平均は四週とも原文があり、整理が完了し、未解析・処理中・失敗・未確認がなく、同じ分類と単位の数量が四週すべてにあるときだけ計算する。
- ある週に該当する分類・単位がない場合は、勝手にゼロを補わず比較不足として扱う。
- 整数の不要な`.0`は表示しない。実数は表示用の数値書式で最大12桁の小数部を扱い、元の保存値は変更しない。

解析状況は原文の整理状況と未確認の成果を区別する。原文件数と未確認成果件数は同じ単位とは限らず、一つの原文から複数の成果が生じる。解析していないこと、記録が存在しないこと、解析済みで完成成果がないことは別の状態である。

## 6. AI説明と保存結果

固定例のAI振り返りには、対象週について保存した日本語の説明・発見・最大2件の提案・判断上の制約が含まれる。重要な発見にはその週または比較週の根拠がある。説明文は集計値を置き換えず、簡潔な数量差はプログラムで別に表示する。

自分の試用記録を変更しても、固定例の分析は更新されず、更新が必要な状態にもならない。両者は別のデータである。言語を変えてもAI本文を翻訳・再生成しない。

## 7. バックエンド接続環境での記録管理

バックエンド接続環境では、原文とその版、整理成果、人による修正、正式分類の確認をサーバーに保存する。解析は原文を保存した後に実行し、遅れて到着した結果で新しい原文や人の修正を上書きしない。失敗しても原文と計時を保全する。新しい分類を自動で正式確定しない。

週の時間は有効区間、成果は原文の記録時刻に基づいて帰属させる。未確認分類は正式な数量合計に入れない。進行中の週には集計時点を示し、完成した過去四週との比較と同じ曜日・時刻までの比較を区別する。比較できる過去の記録、予算、目標などの不足を明示し、短い期間から効率や長期傾向を断定しない。

振り返りは入力データの版、言語、モデル、生成時刻とともに保存する。対象の原文・整理成果・比較履歴が変わると更新が必要な状態を示す。生成中にデータが変わった結果も最新として扱わない。更新失敗時は以前の結果を残す。閲覧と再読み込みは生成操作ではない。この管理はサーバー上の記録を対象とし、ブラウザーの固定例を書き換えるものではない。
